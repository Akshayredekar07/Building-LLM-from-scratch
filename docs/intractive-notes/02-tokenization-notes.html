Introduction: Data Preparation & Sampling

We look at data preparation and sampling in the context of training a Language Model (LM). The central question: How do you prepare input text for training a language model?

The process involves three sequential stages that transform raw text into vector representations a model can learn from.

Special Tokens and Their Role

Special context tokens are added to help the model understand additional special meaning like unknown words or sequence boundaries.

<|unk|>

Unknown token — replaces words not found in the vocabulary. Helps the model handle out-of-vocabulary words gracefully.

<|endoftext|>

End-of-text token — marks the boundary between independent text documents. Helps the model understand context boundaries.

<|bos|> / <|eos|>

Beginning / End of sentence tokens. Mark the start and end of sequences. Used especially in encoder-decoder architectures.

<|pad|>

Padding token — used to make sequences of equal length in batches. Not meaningful; model ignores via attention masking.

04 — Types of Tokenization

Types of Tokenization Algorithms

Three major paradigms for how text gets split into tokens — each with distinct trade-offs between vocabulary size, OOV handling, and computational cost.

1. Word-Based Tokenization
Rule: Each word is treated as a separate token.
Example sentence: "My hobby is playing cricket"
Tokens: [my, hobby, is, playing, cricket]
Advantages
  • Very small vocabulary (e.g. 26 special characters)
  • Solves the OOV problem
Problems
  • Meaning associated with words completely lost
  • The tokenized sequence becomes much longer
2. Subword-Based Tokenization
Rule: Balance between word-based and character-based tokenization — do NOT split frequently used words, DO split into smaller subwords.
Key insight: Subword splitting helps the model learn morphological relationships between words with the same root token.

Word: boy — should NOT split (it's a common word)

Word: boys — SHOULD split into [boy, s]

This allows the model to learn the morphological relationship between "boy" and "boys" — they share the same root token. Subword splitting also helps the model generalize better when words like "root", "tokenization" or different meaning of similar words like "boy", "boy's" are used.

3. Character-Based Tokenization
Example: "my hobby is playing cricket"
Tokens: [m, y, h, o, b, b, y, i, s, p, l, a, y, i, n, g, c, r, i, c, k, e, t]
Advantages
  • Very small vocabulary
  • Few/no unknown tokens (OOV near-zero)
Problems
  • Tokens and tokenizing no meaningful for language understanding
  • Different meaning of similar words like "boy" splits into [b, o, y]
Also: Byte Encoding

A more sophisticated tokenization scheme based on the concept of merging the most frequent byte pairs. It helps the model to learn different forms of root but different in suffixes — words and morphemization are made up of different root and suffixes are used in some synthetic situation. Example: Example tokens with counters on both sides — estimate different positions (markers).

Advantages
Very small vocabulary — uses only 26 English letters + special characters. Only ~30 tokens needed for the entire English language.

Solves OOV Problem — any word can be built from characters, so there are never "unknown" tokens. Works for any language if characters are included.
Problems
Tokens not meaningful for language understanding — individual characters carry no semantic meaning. The model must learn to compose them back into words, which is very hard.

Sequences become much longer — "boy" becomes 3 tokens instead of 1. This explodes sequence length, increasing memory and compute cost quadratically (due to attention).

Different meaning of similar words — "boy" and "boys" both start with [b, o, y] but the model cannot easily distinguish meaning from characters alone.
Subword Splitting Rule

Rule 1: Do not split the more commonly used words frequently into smaller subwords.

Rule 2: Balance between word-based and character-based tokenization — split the more rarely used words or sequence boundaries.

boy → Should NOT split
boys → Should be split into [boy, s]

Example: Tokens and tokenizing on both between words with some root tokens — the model can generalize the morphological relationship.

Subword tokenization example

Sentence: "My hobby is playing cricket" → [my, hobby, is, playing, cricket] (each word separate token since all are common English words — no splitting needed)

06 — BPE Introduction

Byte Pair Encoding (BPE)

BPE is a subword tokenization technique originally proposed in 1994 as a data compression algorithm. It was later adapted as a tokenization scheme for NLP/LLMs.

BPE Purpose: Ensure that most common words in the vocabulary are represented as single tokens, while rarer words are broken down into subword tokens.
Why BPE?
Helps Generalize

It also helps the model to learn that tokenization words and morphemization are made up of different root and suffixes. Used in some synthetic situations.

Root Learning

BPE is subword tokenization. It helps the model to learn different root but different in suffixes (e.g. information, informational, informationally).

Popular Models

BPE is used to train powerful LLMs such as GPT-2, GPT-3, original ChatGPT model. The algorithm is iterative and data-driven.

Data Compression Origins

Originally proposed in 1994 as a data compression algorithm — it replaces the most frequent pair of consecutive symbols with a new symbol that does not already occur in the data.

Core Idea
$$\text{BPE:} \quad \text{replace most frequent adjacent pair} (a, b) \rightarrow \text{new token} \; (ab)$$

What BPE does:

  • It replaces most frequent pair of consecutive symbols
  • Builds a new token that does not already occur
  • It builds with a bite that does not already occur in the algorithm
  • Originally proposed in 1994 as a data compression algorithm

07 — BPE Algorithm

BPE Algorithm: Step-by-Step

The BPE algorithm is iterative. It looks at the token pair frequency table and merges the most frequent adjacent pair at each iteration until a stopping criterion is reached.

Purpose of BPE in LLMs
Raw Text

Update Table

Repeat
Iterative Merging Steps
Step 1 — Preprocessing

Add the end of word follow <|w|> to mark word boundaries. Splitting into characters and count frequencies.

Step 2 — Find Best Pair

Find the most frequent adjacent pair choices from the frequency table.

Step 3 — Merge

Merge the best pair into a new token. Update the frequency table.

Step 4 — Repeat

Repeat until: desired vocabulary size is reached OR a fix number of merges is completed OR most frequent pair is 0.

Iterative Merging in BPE Algorithm

In BPE algorithm, after getting the token frequency table, the next step looks for the most frequent pair mergings:

BPE Iteration — Core Steps
  1. Find the most frequent adjacent pair — from the frequency table
  2. Merge that pair into a new token — update the table
  3. Update the frequency table
  4. Repeat until desired vocabulary size is reached

09 — BPE in Practice

BPE in Practice & Stopping Criteria

How BPE is actually used in production LLMs — stopping criteria, the tiktoken library, and the final vocabulary structure.

Stopping Criteria for BPE
Fixed Vocabulary Size

A fixed vocabulary size is set (e.g. GPT-2 uses 50,257). BPE stops when this many tokens are in the vocabulary.

Maximum Merge Count

A maximum number of merge iterations is defined. BPE runs that many merges regardless of vocabulary size.

Zero Frequency

Often automatically triggers — when the most frequent pair has frequency 0, no more merging is possible. Final table only contains tokens with frequency ≥ 0.

BPE Library: tiktoken

tiktoken is a Python library that implements BPE tokenization used in GPT-2, GPT-3, and GPT-4.

  • Library: tiktoken implements BPE tokenization
  • Used in GPT-2, GPT-3, original ChatGPT model, GPT-4
  • Open provides a Python library called #tiktoken
→ Only contains tokens with frequency ≥ 0

Key BPE Properties
Handles morphology: Words like "low", "lower", "lowest" share the root low as a common subword token. The model learns morphological relationships.
Data-driven: BPE vocabulary is learned entirely from data — frequent patterns in the training corpus get merged first. The vocabulary reflects the actual language distribution.
