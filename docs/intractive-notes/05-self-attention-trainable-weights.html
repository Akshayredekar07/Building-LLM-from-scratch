S1 — Overview

Self-Attention with Trainable Weights

In this section we learn about the self-attention mechanism with trainable weights — the core attention mechanism used in the original Transformer architecture and most modern LLMs including GPT. We previously implemented a simplified self-attention using a scaled dot-product approach (also called the basic form). Now we extend it with three trainable projection matrices that give the model the power to learn what to attend to during training.

What We Want to Compute

For each input token, self-attention computes a context vector — a weighted sum of all input token embeddings, where the weights tell us how much each token should "attend" to every other token.

Compute a context vector $z^i$ for each token $x^i$ as a weighted sum of input token embeddings, where the weights are token-specific and learned via trainable projection matrices.

$$z^i = \sum_{j=1}^{T} \alpha_{ij} \cdot x^j$$

where $\alpha_{ij}$ is the attention weight — how much token $i$ should attend to token $j$ — and $T$ is the total number of input tokens.

Why This Is More Powerful Than Simplified Self-Attention
Simplified SA (Before)

Uses the raw input embeddings $x^i$ directly to compute dot products. No learnable parameters — can't adapt during training.

Trainable SA (Now)

Projects inputs into three separate spaces (query, key, value) using learnable weight matrices $W_Q$, $W_K$, $W_V$ that are updated via gradient descent.

What This Enables

The model learns which semantic relationships matter from the data. The same token can play different roles depending on context.

PyTorch: The Core Idea
Python — Self-attention motivation 
import torch

# concept: simplified vs trainable self-attention
# In simplified SA: Q = K = V = X (raw embeddings)
# In trainable SA: Q = X @ Wq, K = X @ Wk, V = X @ Wv

T, d = 6, 3   # T=6 tokens, d=3 embedding dim
d_k = 2       # output dim for Q, K, V

X = torch.randn(T, d)   # [6, 3] — input token embeddings

# Simplified: no projection, uses raw embeddings
omega_simple = X @ X.T   # [6, 6] — attention scores (raw)

# Trainable: project into Q/K/V spaces first
Wq = torch.randn(d, d_k)  # [3, 2] — query weight matrix
Wk = torch.randn(d, d_k)  # [3, 2] — key weight matrix
Wv = torch.randn(d, d_k)  # [3, 2] — value weight matrix

Q = X @ Wq   # [6, 2] — query matrix
K = X @ Wk   # [6, 2] — key matrix
V = X @ Wv   # [6, 2] — value matrix

omega_trained = Q @ K.T   # [6, 6] — richer attention scores
print("Q shape:", Q.shape)   # torch.Size([6, 2])
print("Attention scores shape:", omega_trained.shape)   # [6, 6]
S2 — Trainable Weight Matrices

The Three Trainable Weight Matrices

We introduce three learnable projection matrices — $W_Q$, $W_K$, $W_V$ — that transform the input embeddings into separate "query", "key", and "value" spaces. These are the parameters that make self-attention powerful: they are updated during model training and are crucial to learn to predict well.

Why Three Separate Projections?
Query (Q)

Represents the current token asking: "How much attention should I pay to other tokens?" The query is the "question".

Key (K)

Represents each token saying: "How relevant am I?" The key is what gets matched against the query.

Value (V)

Carries the actual content to aggregate. Once we know attention weights, we sum values weighted by those weights.

Think of a library database. Your query is what you type in the search box. The book's key is its metadata (title, tags). The book's value is its actual content. High query-key similarity → you get that book's value.

Q: What are $W_Q$, $W_K$, and $W_V$?
They are trainable parameters — their values are initialized randomly and learned via backpropagation. They are not the same as the Q, K, V matrices (which are computed each forward pass by multiplying $X$ with these weights).
Dimensions of W_Q, W_K, W_V
$$W_Q \in \mathbb{R}^{d \times d_k}, \quad W_K \in \mathbb{R}^{d \times d_k}, \quad W_V \in \mathbb{R}^{d \times d_v}$$

Where:

  • $d$ = input embedding dimension
  • $d_k$ = output dimension for Query and Key (must match for dot product)
  • $d_v$ = output dimension for Value (can differ, but usually $d_k = d_v$)
  • In most cases $d_k = d_v = \frac{d_{\text{model}}}{h}$ where $h$ = number of attention heads

BERT uses $d_{\text{model}} = 768$ and $h = 12$ heads, giving $d_k = d_v = 64$. So each weight matrix is $768 \times 64$.

Dimension Arithmetic (Our Example)
$$X \cdot W_Q = \underbrace{(6 \times 3)}_{\text{input}} \cdot \underbrace{(3 \times 2)}_{\text{weight}} = \underbrace{(6 \times 2)}_{Q \text{ matrix}}$$

Each of the 6 tokens gets projected into a 2-dimensional query vector. Same for $K$ and $V$.

PyTorch: Trainable Weight Matrices
Python — Defining W_Q, W_K, W_V as learnable parameters 
import torch
import torch.nn as nn

# concept: trainable projection matrices for self-attention
# X shape: [T, d] — token embeddings
# W_q, W_k, W_v shape: [d, d_k] — learnable weight matrices
# Time: O(T * d * d_k) per projection | Space: O(d * d_k) per matrix

d, d_k = 3, 2   # input dim=3, output dim=2

# Random init — in real training these get updated by optimizer
torch.manual_seed(123)
W_query = nn.Parameter(torch.randn(d, d_k))   # [3, 2]
W_key   = nn.Parameter(torch.randn(d, d_k))   # [3, 2]
W_value = nn.Parameter(torch.randn(d, d_k))   # [3, 2]

# Create example input — 6 tokens, 3-dim embeddings
X = torch.tensor([
    [0.43, 0.15, 0.89],   # x1 "your"
    [0.55, 0.87, 0.66],   # x2 "journey"
    [0.57, 0.85, 0.64],   # x3 "starts"
    [0.22, 0.58, 0.33],   # x4 "one"
    [0.77, 0.25, 0.10],   # x5 "step"
    [0.05, 0.20, 0.55],   # x6 padding token
])   # [6, 3]

# Project into Q, K, V spaces
Q = X @ W_query   # [6, 2] — query matrix
K = X @ W_key     # [6, 2] — key matrix
V = X @ W_value   # [6, 2] — value matrix

print("W_query shape:", W_query.shape)   # [3, 2]
print("Q shape:", Q.shape)               # [6, 2]
print("K shape:", K.shape)               # [6, 2]
print("V shape:", V.shape)               # [6, 2]
Key Takeaway: $W_Q$, $W_K$, $W_V$ are the learnable parameters. They are responsible for learning different semantic roles from the same input — the query asks, the key matches, the value delivers content. This is why self-attention is so expressive.
S3 — Q K V Projections

Computing Query, Key, and Value Matrices

Once we have the trainable weight matrices, we multiply the input embedding matrix $X$ by each of them to get the Query ($Q$), Key ($K$), and Value ($V$) matrices. These three matrices represent the input from three different "perspectives" — each learned to serve a distinct role in the attention mechanism.

The Three Projections
$$Q = X \cdot W_Q \quad \text{(Query space)}$$ $$K = X \cdot W_K \quad \text{(Key space)}$$ $$V = X \cdot W_V \quad \text{(Value space)}$$
Why Project into Separate Spaces?

Instead of using the same embeddings for all purposes, the model learns:

  • Use $Q$ to ask "how much attention should I pay?"
  • Use $K$ to answer "how relevant am I?"
  • Use $V$ to carry the actual content to aggregate

They are responsible for learning different semantic roles from the same input. This is the key insight of multi-head attention — multiple sets of $(W_Q, W_K, W_V)$ learn different relationship patterns simultaneously.

Visual: Token-Level Projection

Each input token $x^i$ gets projected into its own query $q^i$, key $k^i$, and value $v^i$ vectors:

Numerical Example: Computing q² (for "journey")

Let's compute the query vector $q^2$ for the token "journey" ($x^2 = [0.55, 0.87, 0.66]$) using the $W_Q$ matrix:

$$q^2 = x^2 \cdot W_Q = [0.55,\ 0.87,\ 0.66] \cdot \begin{bmatrix} 0.1366 & 0.1025 \\ 0.1841 & 0.7264 \\ 0.3153 & 0.6881 \end{bmatrix}$$
$$q^2_1 = 0.55 \times 0.1366 + 0.87 \times 0.1841 + 0.66 \times 0.3153$$ $$= 0.0751 + 0.1602 + 0.2081 = 0.4434$$
$$q^2_2 = 0.55 \times 0.1025 + 0.87 \times 0.7264 + 0.66 \times 0.6881$$ $$= 0.0564 + 0.6320 + 0.4542 = 1.1426$$
$$\therefore \quad q^2 = [0.4434,\ 1.1426] \in \mathbb{R}^{2}$$
Note: Each token's query, key, and value are always 2D vectors in this example ($d_k = 2$). But in BERT they are 64-dimensional, and in GPT-3 they are 128-dimensional per head.

S4 — Attention Scores

Computing Attention Scores

Attention scores $\omega_{ij}$ measure how much token $i$ should attend to token $j$. They are computed as the dot product between the query of token $i$ and the key of token $j$. A high dot product means the query and key are well aligned — token $i$ finds token $j$ relevant.

The Attention Score Formula
$$\omega_{ij} = q^i \cdot k^j$$

For all tokens at once, this is a single matrix multiplication:

$$\Omega = Q \cdot K^\top \quad \in \mathbb{R}^{T \times T}$$

Result: a $T \times T$ matrix. Entry $\Omega[i,j]$ = how much token $i$ attends to token $j$. Shape: $(6 \times 2) \cdot (2 \times 6) = 6 \times 6$.

S5 — Softmax & Scaling

Scaled Dot-Product Attention: Softmax and Normalization

Raw attention scores $\omega_{ij}$ can be any real number. We need to convert them into probabilities (attention weights $\alpha_{ij}$) that sum to 1. We do this with softmax — but first we scale down the scores by dividing by $\sqrt{d_k}$ to prevent the softmax from saturating.

Why Scaling? — The Problem with Large Dot Products
Problem

When $d_k$ is large, dot products grow in magnitude. Computing dot products of vectors with mean 0, variance 1 → the dot product has variance $d_k$. So standard deviation grows as $\sqrt{d_k}$.

Effect on Softmax

Large values push softmax into a very "peaked" distribution — almost all weight on one token, near zero on others. Gradients become tiny → slower learning.

Solution

Divide by $\sqrt{d_k}$ before softmax. This keeps the variance of the dot products at ~1 regardless of $d_k$, giving softmax a well-conditioned input.

Full Formula: Scaled Dot-Product Attention
$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right) V$$

Step by step:

  1. Compute raw scores: $\Omega = QK^\top$ — shape $[T \times T]$
  2. Scale: $\hat{\Omega} = \Omega / \sqrt{d_k}$ — prevents softmax saturation
  3. Apply softmax row-wise: $A = \text{softmax}(\hat{\Omega})$ — shape $[T \times T]$, rows sum to 1
  4. Weighted sum of values: $Z = A \cdot V$ — shape $[T \times d_v]$

$$\hat{\omega}_{11} = 0.778 / 1.414 = 0.550$$ $$\hat{\omega}_{12} = 1.058 / 1.414 = 0.748$$ $$\hat{\omega}_{13} = 1.036 / 1.414 = 0.733$$ $$\hat{\omega}_{14} = 0.532 / 1.414 = 0.376$$ $$\hat{\omega}_{15} = 0.152 / 1.414 = 0.107$$ $$\hat{\omega}_{16} = 0.321 / 1.414 = 0.227$$
Note: Scaling makes the inputs to softmax more moderate — preventing the exponentials from becoming astronomically large.
STEP 3 OF 4
Apply Softmax

$\text{softmax}(z_i) = \frac{e^{z_i}}{\sum_j e^{z_j}}$. Compute exponentials:

$$e^{0.550} = 1.733,\quad e^{0.748} = 2.113,\quad e^{0.733} = 2.081$$ $$e^{0.376} = 1.457,\quad e^{0.107} = 1.113,\quad e^{0.227} = 1.255$$
$$\text{Sum} = 1.733 + 2.113 + 2.081 + 1.457 + 1.113 + 1.255 = 9.752$$
$$\alpha_{11} = 1.733/9.752 = 0.178,\quad \alpha_{12} = 2.113/9.752 = 0.217$$ $$\alpha_{13} = 2.081/9.752 = 0.213,\quad \alpha_{14} = 1.457/9.752 = 0.149$$ $$\alpha_{15} = 1.113/9.752 = 0.114,\quad \alpha_{16} = 1.255/9.752 = 0.129$$

Verify: $0.178 + 0.217 + 0.213 + 0.149 + 0.114 + 0.129 = 1.000$ ✓

Step 1 of 4
Softmax Function — Full Formula
$$\text{softmax}(z_i) = \frac{e^{z_i}}{\displaystyle\sum_{j=1}^{T} e^{z_j}}$$

In practice, a numerically stable version subtracts the max before exponentiating:

$$\text{softmax}(z_i) = \frac{e^{z_i - \max(z)}}{\displaystyle\sum_{j} e^{z_j - \max(z)}}$$

This prevents overflow when $z_i$ values are large, while giving identical results mathematically.

Softmax converts any real-valued scores into a valid probability distribution (values in $(0,1)$ that sum to 1). This means attention weights can be interpreted as "percentage of attention" allocated to each token.

For each token $i$: attention it pays to itself + attention to all other tokens = 1.0.

PyTorch: Scaling + Softmax
Python — Scaled attention + softmax = attention weights 
import torch
import torch.nn.functional as F
import math

# concept: scaled dot-product attention — scores → weights
# omega shape: [T, T], attention_weights shape: [T, T]
# Each row of attention_weights sums to 1.0

omega = torch.tensor([
    [0.778, 1.058, 1.036, 0.532, 0.152, 0.321],
    [1.098, 1.498, 1.466, 0.744, 0.213, 0.452],
    [1.098, 1.498, 1.466, 0.744, 0.213, 0.452],
    [0.494, 0.674, 0.660, 0.335, 0.096, 0.204],
    [0.220, 0.300, 0.294, 0.149, 0.043, 0.091],
    [0.750, 1.023, 1.001, 0.509, 0.146, 0.310],
])   # [6, 6]

d_k = 2

# Step 1: Scale
omega_scaled = omega / math.sqrt(d_k)   # [6, 6] — prevents saturation

# Step 2: Softmax row-wise (dim=-1 = across columns)
attention_weights = F.softmax(omega_scaled, dim=-1)   # [6, 6]

print("Attention weights for 'your' (row 0):")
print(attention_weights[0].round(decimals=4))
print("Row sum (should be 1.0):", attention_weights[0].sum().item())
print("Full attention weight matrix:")
print(attention_weights.round(decimals=3))
Key Takeaway: Scaling by $1/\sqrt{d_k}$ is not optional — it is critical for training stability. Without it, large $d_k$ values cause softmax saturation, leading to vanishing gradients. The formula $\text{Attention}(Q,K,V) = \text{softmax}(QK^\top / \sqrt{d_k}) \cdot V$ is the canonical scaled dot-product attention.
S6 — Context Vectors

Computing Context Vectors

The final step in self-attention is using the attention weights $\alpha_{ij}$ to compute a context vector $z^i$ for each token. The context vector is a weighted sum of all value vectors — it represents the token's "context-aware" representation after attending to every other token.

Context Vector Formula
$$z^i = \sum_{j=1}^{T} \alpha_{ij} \cdot v^j$$

In matrix form for all tokens at once:

$$Z = A \cdot V \quad \in \mathbb{R}^{T \times d_v}$$

Where $A$ is the $[T \times T]$ attention weight matrix and $V$ is the $[T \times d_v]$ value matrix. Result: one $d_v$-dimensional context vector per token.

Intuition: What Q, K, V Represent in a Database Analogy
Query (Q)

Analogous to a search query in a database. It represents the current token's information need. The model uses $q^i$ to find which other tokens are relevant to token $i$.

Key (K)

In attention mechanism, the sequence has a key that each item in the input sequence is written in. Keys are used to determine relevance — high $q \cdot k$ similarity means the model will focus on that token.

Value (V)

Represents the actual content or information. Once we know how relevant each token is (via attention weights), we take a weighted sum of values to construct the output. It determines what information flows forward.

Keys: In attention, the sequence has a key that each item is written in. The key represents each input token. It is used to determine relevance because the model determines which keys (input tokens) are most relevant to focus on.

Values: It represents the actual content of the input. The model outputs a value, then for each "journey", does NOT just give us query visits to all tokens — it gives us a representation of each context corresponding to the attention stops.

PyTorch: Full Self-Attention Forward Pass
Python — Complete self-attention computation 
import torch
import torch.nn.functional as F
import math

# concept: full scaled dot-product self-attention
# X: [T, d], Wq/Wk/Wv: [d, dk]
# Z: [T, dv] — context vectors for all tokens
# Time: O(T²·dk + T·dk·dv) | Space: O(T² + T·dv)

torch.manual_seed(42)
T, d, d_k = 6, 3, 2
d_v = d_k   # value dim = key dim

X = torch.randn(T, d)   # [6, 3]

# Learnable weight matrices
W_q = torch.randn(d, d_k)   # [3, 2]
W_k = torch.randn(d, d_k)   # [3, 2]
W_v = torch.randn(d, d_v)   # [3, 2]

# Step 1: Project into Q, K, V
Q = X @ W_q   # [6, 2]
K = X @ W_k   # [6, 2]
V = X @ W_v   # [6, 2]

# Step 2: Compute scaled attention scores
scores = (Q @ K.T) / math.sqrt(d_k)   # [6, 6]

# Step 3: Softmax → attention weights
alpha = F.softmax(scores, dim=-1)   # [6, 6], rows sum to 1

# Step 4: Weighted sum of values → context vectors
Z = alpha @ V   # [6, 2] — context vectors

print("Context vectors Z:")
print(Z.round(decimals=4))
print("Z shape:", Z.shape)   # [6, 2]
print("Attn weights row 0 (your):", alpha[0].round(decimals=4))
Key Takeaway: Context vector $z^i$ encodes a contextually-aware representation of token $i$ — it has "seen" all other tokens via the attention weights. High attention weight $\alpha_{ij}$ means token $i$ "borrows" more information from token $j$'s value vector. This is how transformers capture long-range dependencies.
S7 — Implementation

Implementing Self-Attention as a Python Class

Now we put everything together into a compact, reusable SelfAttention Python class. Self-attention involves the three trainable weight matrices $W_Q$, $W_K$, $W_V$ transforming input data into query, key, and value vectors — then applying scaled dot-product attention to produce context vectors.

Complete Workflow (from notes)
Input X [T×d]
→
Q=XWq, K=XWk, V=XWv
→
Scores = QKᵀ/√dk
→
Softmax → α
→
Z = αV

The class holds three weight matrices as trainable parameters: $W_Q$ (projects input to query space), $W_K$ (projects input to key space), $W_V$ (projects input to value space). These are the components of the attention mechanism that give it expressive power.

A huge matrix transforms the input data into query, key, and value, which are the current query token and its corresponding context vector.

PyTorch: Self-Attention Class
Python — Compact SelfAttention nn.Module 
import torch
import torch.nn as nn
import torch.nn.functional as F
import math

# concept: self-attention with trainable W_q, W_k, W_v
# Forward: X [T, d] → Z [T, d_v] (context vectors)
# Trainable params: 3 matrices of shape [d, d_k]

class SelfAttention(nn.Module):
    def __init__(self, d_in, d_out, bias=False):
        super().__init__()
        # Three linear layers = three weight matrices (bias=False to match math)
        self.W_query = nn.Linear(d_in, d_out, bias=bias)  # [d_in, d_out]
        self.W_key   = nn.Linear(d_in, d_out, bias=bias)  # [d_in, d_out]
        self.W_value = nn.Linear(d_in, d_out, bias=bias)  # [d_in, d_out]
        self.d_out = d_out

    def forward(self, x):
        # x: [T, d_in]  — token embeddings
        Q = self.W_query(x)   # [T, d_out]
        K = self.W_key(x)     # [T, d_out]
        V = self.W_value(x)   # [T, d_out]

        # Scaled dot-product attention
        scores = (Q @ K.transpose(-2, -1)) / math.sqrt(self.d_out)   # [T, T]
        alpha  = F.softmax(scores, dim=-1)   # [T, T] — attention weights
        z      = alpha @ V                      # [T, d_out] — context vectors
        return z

# ── Test ──
torch.manual_seed(42)
d_in, d_out = 3, 2

    [0.77, 0.25, 0.10],   # "step"
    [0.05, 0.20, 0.55],   # padding
])   # [6, 3]

Z = sa(X)
print("Context vectors:")
print(Z.detach().round(decimals=4))

The Complete Self-Attention Recipe:
  1. Project inputs: $Q = XW_Q$, $K = XW_K$, $V = XW_V$
  2. Compute scores: $\Omega = QK^\top$
  3. Scale: $\hat{\Omega} = \Omega / \sqrt{d_k}$
  4. Normalize: $A = \text{softmax}(\hat{\Omega})$ row-wise
  5. Aggregate: $Z = AV$ — context vectors, one per token
The three weight matrices $W_Q$, $W_K$, $W_V$ are the only trainable parameters — they learn to project the input into spaces where meaningful attention patterns emerge.
