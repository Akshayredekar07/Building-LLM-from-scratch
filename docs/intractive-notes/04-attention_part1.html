S1 — Overview

4 Types of Attention in LLMs

The attention mechanism is the core building block of modern LLMs. There are 4 main variants, each building on the previous. Understanding them in order helps you see why transformers replaced RNNs.

The 4 Attention Types
1. Simplified Self-Attention

No trainable weights. Used to introduce the broad idea of how a token attends to others. Good for learning the concept from scratch.

2. Self-Attention

Has trainable weight matrices ($W_Q$, $W_K$, $W_V$). Forms the basis of the full mechanism used in LLMs like GPT.

3. Multi-Head Attention

Runs multiple attention heads in parallel, allowing the model to simultaneously attend to different representation subspaces of the input.

4. Causal Attention

Each token can only attend to previous and current tokens — not future ones. Used in autoregressive models (GPT family).

Why this order matters: Each type is a refinement: Simplified SA → SA (add weights) → Multi-Head SA (add parallelism) → Causal SA (add masking). LLMs use Multi-Head Causal Attention.
What does "Self" in Self-Attention mean?
Traditional Attention

Focuses on the relationship between 2 different sequences — e.g. source sentence vs target sentence in Bahdanau (encoder states ↔ decoder state).

Self-Attention

The mechanism learns relationships between various parts of the input itself — such as words within a single sentence. The sequence attends to itself.

In self-attention, the "self" refers to the mechanism's ability to compute attention weights by relating different positions within a single input sequence. This is in contrast to traditional attention where the focus is on relationships between different elements of two different sequences.

Long-Range Dependency: Why Word Order Matters

"The cat that was sitting on the mat, which was next to the dog, jumped."

French: "Le chat qui était assis sur le tapis, qui était à côté du chien, a sauté."

The key action "jumped" depends on the subject "cat" — but they are separated by a long relative clause. The model must also understand: "that was sitting on the mat" and "next to the dog".

RNN Fails Here

RNN must compress "the cat…the mat…the dog" into a single fixed vector. By the time it reaches "jumped", context about "cat" has been overwritten.

Attention Solves This

At each decoding step the model can look back at the entire input and decide which parts are most relevant. "jumped" can directly attend to "cat" regardless of distance.

Key Insight: Certain words in the translation need access to words that appear earlier or later in the original sentence. Word order differs across languages — we need a mechanism that can look at the full sentence at once.
PyTorch: Encoder-Decoder Concept
Python — Simple Encoder-Decoder Sketch (Conceptual) 
# Encoder-Decoder: compress input → context → generate output
# encoder_out: final hidden state (context vector)
# Precondition: vocab_size > 0, embed_dim matches hidden_dim
# Time: O(T) encoder steps + O(S) decoder steps

import torch
import torch.nn as nn

class SimpleEncoder(nn.Module):
    def __init__(self, vocab_size, embed_dim, hidden_dim):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, embed_dim)
        self.rnn = nn.GRU(embed_dim, hidden_dim, batch_first=True)

    def forward(self, token_ids):
        x = self.embed(token_ids)
        _, h_n = self.rnn(x)
        return h_n  # ← bottleneck for long sequences

# Dry run: token_ids=[5,2,8,1] → embed → [1,4,16] → rnn → h_n [1,1,32]
encoder = SimpleEncoder(vocab_size=1000, embed_dim=16, hidden_dim=32)
tokens = torch.tensor([[5, 2, 8, 1]])
context = encoder.forward(tokens)
print("context vector shape:", context.shape)  # [1, 1, 32]
S2 — RNN Problem

RNN Encoder-Decoder Architecture & Its Flaws

Before transformers, RNNs were the most popular encoder-decoder architecture. Understanding exactly why they fail motivates the attention mechanism.

How the RNN Encoder-Decoder Works
  1. Receives input text (e.g. German sentence)
  2. Processes it sequentially — one token at a time
  3. At each step, updates its hidden state (internal memory)
  4. After the last token, produces a final hidden state — the context vector
  1. Receives the final hidden state from the encoder (this single vector is all it gets)
  2. Updates its own hidden state at each decoding step
  3. Generates the output translation one word at a time
How RNN Processes Input — Step by Step
  1. Receive input text (e.g. German sentence)
  2. Process it sequentially — one token at a time, left to right
  3. At each step, update the hidden state $h_t$ using the current token embedding and the previous hidden state: $h_t = f(x_t, h_{t-1})$
  4. After the last token, produce a final hidden state $h_{ ext{final}}$ — the encoder tries to capture the full meaning here
  5. The decoder uses only this $h_{ ext{final}}$ to generate the output — one word at a time
Key issue: The output from the previous step is fed as input to the current step. This means errors accumulate and early information fades as the sequence grows longer.

The Big Problem: Information Bottleneck
Critical Issue: The RNN compresses the entire input into a single fixed-size vector. For long sentences, crucial early information is overwritten by later tokens.
No Direct Access

Decoder cannot directly access earlier encoder hidden states during decoding. It relies solely on the current hidden state $h_{ ext{final}}$.

Loss of Context

This leads to loss of context, especially in complex sentences where dependencies span long distances — e.g. "cat…jumped" 8 words apart.

Single Vector Limit

Encoder compresses the entire input sequence into a single fixed-size hidden state vector. Very long sentences are simply too much for one vector.

Sequential Only

Tokens processed one by one — no parallelism. Slow to train, especially on long inputs.

"The cat that was sitting on the mat, which was next to the dog, jumped."

By the time the RNN reaches "jumped", the hidden state has been updated many times and the information about "cat" — the actual subject — has been partially overwritten. RNN works fine for short sentences but struggles for long ones because it has no direct access to previous words in the input.

# RNN bottleneck: entire sequence compressed to fixed-size vector
# h_all: all hidden states [batch, seq_len, hidden] — discarded by plain decoder
# h_final: last hidden state — only this goes to decoder
import torch, torch.nn as nn

rnn = nn.GRU(input_size=16, hidden_size=64, batch_first=True)
fake_embeddings = torch.randn(1, 12, 16)  # 12-token sentence
h_all, h_final = rnn(fake_embeddings)

print("final context vector:", h_final.shape) # [1,  1, 64]  ← bottleneck
# 12 tokens → 64 numbers. Lossy for long sequences.
Key Takeaway: The RNN must fit all information into one fixed vector. Attention solves this by giving the decoder direct access to all encoder states with learned weights.
S3 — Bahdanau Attention

Bahdanau Attention Mechanism (2014)

Dzmitry Bahdanau et al. modified the encoder-decoder RNN so the decoder could selectively access different parts of the encoder's hidden states at each decoding step.

Key Idea — Dotted Line Intuition: Imagine dotted lines connecting each output token to each input token. The width (thickness) of the dotted line is proportional to how important that input token is for generating the current output token. When generating "you", the thick line goes to "du" — the model learned this alignment.
Why is this better? Using the attention mechanism, the text-generating decoder part of the network can selectively access all input tokens at each step. Some tokens are more important than others for generating a given output — this importance is determined by the attention weights.
Bridge to Transformers (2017)

In 2014, Bahdanau attention still required RNNs. Just 3 years later, researchers found that the RNN architecture is not required at all for building deep neural networks for NLP. The original Transformer architecture (Vaswani et al., 2017 — "Attention Is All You Need") proposed a self-attention mechanism inspired by Bahdanau — but without any RNNs whatsoever.

Python — Bahdanau Attention Score Calculation 
# Bahdanau attention: score each encoder state vs current decoder state
# Time: O(src_len) per decoding step
import torch, torch.nn as nn, torch.nn.functional as F

class BahdanauAttention(nn.Module):
    def __init__(self, hidden_dim):
        super().__init__()
        self.score_net = nn.Linear(hidden_dim * 2, 1)

    def forward(self, encoder_states, decoder_state):
        src_len = encoder_states.shape[1]
        dec_expanded = decoder_state.expand(-1, src_len, -1)
        combined = torch.cat([encoder_states, dec_expanded], dim=-1)
        scores = self.score_net(combined)
        attn_weights = F.softmax(scores, dim=1)
        context = (attn_weights * encoder_states).sum(dim=1, keepdim=True)
        return context, attn_weights

# Dry run: enc[1,4,32] × dec[1,1,32] → weights[1,4,1] → ctx[1,1,32]
attn = BahdanauAttention(hidden_dim=32)
enc = torch.randn(1, 4, 32)
dec = torch.randn(1, 1, 32)
ctx, weights = attn.forward(enc, dec)
print("context:", ctx.shape, "weights:", weights.squeeze())
Key Result: Bahdanau gives the decoder a dynamic, step-dependent view of the input. Huge improvement — but still tied to RNNs. Transformer (2017) removed the RNN entirely.
S4 — Self-Attention

Self-Attention — The Heart of Transformers

Self-attention allows each position in the input sequence to attend to all other positions in the same sequence. It is the key component of GPT, BERT, and all modern LLMs.

What Makes It "Self"?
Traditional Attention

Relates elements between 2 different sequences (source → target, as in Bahdanau).

Self-Attention

Relates elements within the same sequence. The input attends to itself — hence "self".

Why Self-Attention Beats RNN for Long-Range
Dynamic focus: At each position, the model assigns different importance weights to every other position — directly relating "cat" and "jumped" even 10 words apart, no bottleneck.
Python — Self-Attention Pipeline (Conceptual) 
# Q=K=V=x in self-attention (same sequence for all three)
import torch, torch.nn as nn

d_model = 64
attn_layer = nn.MultiheadAttention(embed_dim=d_model, num_heads=4, batch_first=True)
x = torch.randn(1, 5, d_model)  # "your journey starts one step" — 5 tokens

attn_out, attn_weights = attn_layer(x, x, x)  # Q=K=V=x
print("input:", x.shape)              # [1, 5, 64]
print("output:", attn_out.shape)      # [1, 5, 64]
print("attn weights:", attn_weights.shape)  # [1, 5, 5]
Self-attention computes attention weights by relating different positions within a single input sequence. No separate source/target pair needed.
Formal Definition
Self-attention is a mechanism that allows each position of the input sequence to attend to all positions in the same sequence when computing a representation of that sequence.
Key Property 1 — All Positions

Every token can directly attend to every other token, regardless of distance. No bottleneck, no fading memory.

Key Property 2 — Parallel

Unlike RNNs, all attention computations happen in parallel. This is why Transformers train so much faster.

Key Property 3 — Context-Aware

Each output vector (context vector) encodes information about the token and its relationships to all other tokens.

Dynamic Focus: Long-Range Dependencies

Consider: "The cat that was sitting on the mat, which was next to the dog, jumped."

→ At each decoding step, the model can look back at the entire input sequence and decide which parts are most relevant.

→ When predicting the next word after "jumped", the attention mechanism focuses on "cat" — even though they are far apart.

→ Dynamic focus on different parts of the input allows the model to learn long-range dependencies more effectively than any RNN.

Self-Attention as Key Component of Modern LLMs
Self-attention is the key component of contemporary LLMs based on the Transformer architecture — GPT series, BERT, LLaMA, and all modern language models. It replaced RNNs because it handles long-range dependencies directly, trains in parallel, and scales efficiently with data and compute.
S5 — Simple Self-Attention

Simple Self-Attention — Step by Step

In this section we implement a simple variant of self-attention, free from any trainable weights. The goal is to understand the raw mechanics before adding learnable parameters. We work through computing context vectors for all tokens in "your journey starts one step".

2. Goal of Simple Self-Attention
Goal: Calculate a context vector $z^i$ for each input token embedding $x^i$.
What is $z^i$?

A context vector is an enriched embedding that encodes: (1) information about $x^i$ itself, and (2) context of all other tokens $x^1 \dots x^T$ in the sequence.

Why do we need it?

The raw embedding $x^i$ has no knowledge of surrounding words. The context vector $z^i$ is context-aware — the same word gets a different $z^i$ depending on its neighbours.

Trainable Weights Later

In simple SA there are no trainable weights. Later we add $W_Q$, $W_K$, $W_V$ so the model learns to construct useful context vectors for predicting the next token.

Focus Example: Second Token $x^2$ ("journey")

For token $x^2$, the corresponding context vector is $z^2$. This vector will summarize:
— the content of $x^2$ itself ("journey")
— contextual relationships with all other tokens $x^1, x^3, x^4, x^5$

This makes $z^2$ a context-aware representation of token 2. The same process is then repeated for every other token to produce $z^1, z^3, z^4, z^5$.

The 3 Steps of Simple Self-Attention
STEP 1 of 3
Compute Attention Scores ω

Dot product between query token x² and every token in the sequence.

$$\omega_{2i} = x^2 \cdot x^i \qquad \omega_{21} = [0.5,0.2,0.1]\cdot[0.4,0.1,0.8] = 0.30$$ $$\omega_{22} = [0.5,0.2,0.1]\cdot[0.5,0.2,0.1] = 0.30 \qquad \omega_{23} = 0.31$$
Dot product = similarity. Higher dot product → vectors more aligned → tokens more related.
STEP 2 of 3
Normalize → Attention Weights α

Apply softmax to raw scores to convert them into probabilities.

$$\alpha_{2i} = \frac{e^{\omega_{2i}}}{\sum_j e^{\omega_{2j}}}$$ $$[\omega_{21},\dots] = [0.9,1.4,1.4,\dots,1.0] \xrightarrow{\text{softmax}} [\alpha_{21},\dots] = [0.1,0.2,0.2,\dots,0.1]$$ $$\sum_i \alpha_{2i} = 1.0$$
Why softmax? Forces all weights ∈ [0,1] and sum=1 — interpretable as "percentage of attention".
STEP 3 of 3
Compute Context Vector z²

Multiply each embedding by its attention weight, sum all results.

$$z^2 = \sum_{i=1}^{T} \alpha_{2i} \cdot x^i = 0.1\cdot x^1 + 0.2\cdot x^2 + 0.2\cdot x^3 + \dots \approx [0.4,\,0.6,\,0.5]$$
z² = [0.4, 0.6, 0.5] — context-aware representation of "journey", aggregating info from the full sequence.
Step 1 of 3
Python — Simple Self-Attention (No Trainable Weights) 
# X [T,d] → omega [T,T] → alpha [T,T] → Z [T,d]
# Time: O(T² × d) | Space: O(T²)
import torch, torch.nn.functional as F

X = torch.tensor([
    [0.4, 0.1, 0.8],  # x1: your
    [0.5, 0.2, 0.1],  # x2: journey  ← query
    [0.5, 0.3, 0.0],  # x3: starts
    [0.2, 0.5, 0.4],  # x4: one
    [0.0, 0.8, 0.9],  # x5: step
])  # [5, 3]

omega = X @ X.T                       # [5,5] raw scores
alpha = F.softmax(omega, dim=-1)    # [5,5] weights
Z     = alpha @ X                     # [5,3] context vectors

print("alpha:\n", alpha.round(decimals=2))
print("z2 (journey):", Z[1])
S6 — Attention Scores

Step 1: Computing Attention Scores ω

The first concrete step of self-attention: computing attention scores (ω, omega) measuring raw relevance between every pair of tokens using the dot product.

The Dot Product Formula
$$\omega_{2i} = x^2 \cdot x^i = \sum_{k=1}^{d} x^2_k \cdot x^i_k$$

The dot product measures geometric similarity — how much two vectors point in the same direction. A higher score means the two tokens are more related.

Full Calculation: All 5 Scores for Query $x^2$

Query: $x^2 = [0.5,\; 0.2,\; 0.1]$ — "journey"

$$\omega_{21} = x^2 \cdot x^1 = (0.5)(0.4) + (0.2)(0.1) + (0.1)(0.8) = 0.20 + 0.02 + 0.08 = \mathbf{0.30}$$ $$\omega_{22} = x^2 \cdot x^2 = (0.5)(0.5) + (0.2)(0.2) + (0.1)(0.1) = 0.25 + 0.04 + 0.01 = \mathbf{0.30}$$ $$\omega_{23} = x^2 \cdot x^3 = (0.5)(0.5) + (0.2)(0.3) + (0.1)(0.0) = 0.25 + 0.06 + 0.00 = \mathbf{0.31}$$ $$\omega_{24} = x^2 \cdot x^4 = (0.5)(0.2) + (0.2)(0.5) + (0.1)(0.4) = 0.10 + 0.10 + 0.04 = \mathbf{0.24}$$ $$\omega_{25} = x^2 \cdot x^5 = (0.5)(0.0) + (0.2)(0.8) + (0.1)(0.9) = 0.00 + 0.16 + 0.09 = \mathbf{0.25}$$
Resulting score vector: $\omega_{2,:} = [0.30,\ 0.30,\ 0.31,\ 0.24,\ 0.25]$
Notice $\omega_{23}$ is slightly highest — "starts" is most similar to "journey" in this embedding space. These are the raw scores, not yet probabilities.

S7 — Normalize

Step 2: Normalizing Attention Scores → Weights

Raw scores ω can be any real number. We must normalize them into probabilities α ∈ [0,1] that sum to 1. The standard approach is softmax.

The Softmax Function
$$\text{softmax}(x_i) = \frac{e^{x_i}}{\sum_{j=1}^{n} e^{x_j}}$$ $$\text{All outputs} \in [0,1] \quad \text{and} \quad \sum_i \text{softmax}(x_i) = 1$$
  • Bounded: All outputs ∈ [0,1] — interpretable as probabilities
  • Sums to 1: Total attention always 100%, split across tokens
  • Differentiable: Allows gradient-based training
  • Amplifies differences: Higher scores get disproportionately more weight
Applying Softmax to Our Example — Full Calculation

Using the scores computed in S6: $\omega_{2,:} = [0.30,\ 0.30,\ 0.31,\ 0.24,\ 0.25]$

$$\text{sum of exponentials} = e^{0.30} + e^{0.30} + e^{0.31} + e^{0.24} + e^{0.25}$$ $$= 1.350 + 1.350 + 1.363 + 1.271 + 1.284 = 6.618$$
$$\alpha_{21} = \frac{e^{0.30}}{6.618} = \frac{1.350}{6.618} \approx 0.204 \quad \alpha_{22} = \frac{e^{0.30}}{6.618} \approx 0.204$$ $$\alpha_{23} = \frac{e^{0.31}}{6.618} = \frac{1.363}{6.618} \approx 0.206 \quad \alpha_{24} = \frac{e^{0.24}}{6.618} \approx 0.192 \quad \alpha_{25} = \frac{e^{0.25}}{6.618} \approx 0.194$$

★ Numerical Stability Trick: Subtract Max

Problem: If scores are large (e.g. 400), $e^{400}$ causes floating-point overflow (infinity). PyTorch and TensorFlow both use this trick internally.

Solution: Subtract the max value from all scores before applying the exponential. This does not change the output, but keeps all exponentials within a safe numerical range.

$$\text{Stable Softmax}(x_i) = \frac{e^{x_i - \max(x)}}{\sum_j e^{x_j - \max(x)}}$$

Example 1: Inputs $[1, 2, 3]$ → subtract max (3) → $[-2, -1, 0]$

$$e^{[-2,-1,0]} = [0.135,\ 0.368,\ 1.000] \quad \text{sum} = 1.503$$ $$\text{Softmax} = [0.09,\ 0.24,\ 0.66] \quad \checkmark$$

Example 2: Inputs $[400, 1, 2]$ → without stability: $e^{400} = $ overflow ✗

$$[400,1,2] - 400 = [0, -399, -398] \rightarrow e^{[0,-399,-398]} \approx [1.0, \approx 0, \approx 0]$$ $$\text{Softmax} = [0.99,\ 0.00,\ 0.00] \quad \checkmark \text{ no overflow}$$

Python — Softmax Normalization with Numerical Stability 
import torch, torch.nn.functional as F

omega = torch.tensor([0.9, 1.4, 1.4, 1.1, 1.0])
alpha = F.softmax(omega, dim=0)  # internally subtracts max

print("omega:", omega)
print("alpha:", alpha.round(decimals=3))
print("sum:",   alpha.sum().item())  # 1.0

# Manual stable softmax
omega_safe   = omega - omega.max()
alpha_manual = omega_safe.exp() / omega_safe.exp().sum()
print("manual:", alpha_manual.round(decimals=3))
After softmax: Attention weights α ∈ [0,1] summing to 1. Each α₂ᵢ = "how much attention journey pays to token i". Ready for step 3.
S8 — Context Vector

Step 3: Computing the Context Vector z²

We have attention weights α summing to 1. The final step: compute z² — a weighted sum of all input token embeddings. This is the core of the "attend and aggregate" operation.

The Weighted Sum Formula
$$z^i = \sum_{j=1}^{T} \alpha_{ij} \cdot x^j$$

For each token $i$, we multiply its attention weights by the corresponding token embeddings and sum everything together. This produces one context vector per token.

$$z^2 = \alpha_{21}\cdot x^1 + \alpha_{22}\cdot x^2 + \alpha_{23}\cdot x^3 + \alpha_{24}\cdot x^4 + \alpha_{25}\cdot x^5$$

We compute one z per token. For T tokens → T context vectors $[z^1,\dots,z^T]$, each context-aware. As matrix: $Z = \alpha X \in \mathbb{R}^{T\times d}$.
Python — Context Vector Computation (Step 3) 
# Z = alpha @ X  →  [T,T] @ [T,d] = [T,d]
import torch, torch.nn.functional as F

X = torch.tensor([
    [0.4,0.1,0.8],[0.5,0.2,0.1],[0.5,0.3,0.0],[0.2,0.5,0.4],[0.0,0.8,0.9],

Full pipeline: $X \xrightarrow{\text{dot product}} \omega \xrightarrow{\text{softmax}} \alpha \xrightarrow{\text{weighted sum}} Z$. Each row of Z is a context-enriched token representation.
Step 4: Computing Context Vectors for ALL Tokens
Important: We computed $z^2$ for "journey" above — but we must repeat the same 3 steps for every token in the sequence. We get one context vector per token: $z^1, z^2, z^3, z^4, z^5$.

We can extend the same computation to calculate attention weights and context vectors for all input tokens efficiently. We calculate the full attention weight matrix $\Omega$ as follows:

$$\Omega = X \cdot X^\top \quad \in \mathbb{R}^{T \times T}$$ $$\text{Row } i \text{ of } \Omega = [\omega_{i1},\ \omega_{i2},\ \dots,\ \omega_{iT}] \quad \leftarrow \text{attention scores for token } i$$

Each entry $\omega_{ij}$ = dot product of $x^i$ and $x^j$. Row = query token, Column = key token.

Then: Softmax Each Row → α Matrix, Then Z = αX
$$A = \text{softmax}(\Omega) \quad \in \mathbb{R}^{T \times T} \quad \text{(softmax applied row-wise)}$$ $$Z = A \cdot X \quad \in \mathbb{R}^{T \times d} \quad \text{(each row = one context vector)}$$
Result: $Z$ has the same shape as $X$ — same $T$ tokens, same $d$ dimensions. But now each row $z^i$ is context-aware: it encodes information about token $i$ and its relationships to all other tokens in the sequence. This is the fundamental power of self-attention.
Later we will add trainable weights $W_Q$, $W_K$, $W_V$ that help the LLM learn to construct these context vectors so they are actually useful for generating the next token. Without training, the context vectors encode raw embedding similarity — not semantic meaning.
S9 — Weight Matrices

Self-Attention with Trainable Weight Matrices

Real self-attention introduces three learned projection matrices $W_Q$, $W_K$, $W_V$ that transform each token into a query, key, and value vector — trained via backpropagation.

The Three Projections
Query (Q)

What the current token is looking for. The search query — what info does this token need from others?

Key (K)

What each token offers as an identifier. Scores = matching query against all keys.

Value (V)

The actual content that gets aggregated. Once relevance is known via Q·K, values get mixed into output.

Diagram: $W_Q$, $W_K$, $W_V$ Projections
The Full Formula
$$Q = XW_Q,\quad K = XW_K,\quad V = XW_V$$ $$\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

Without scaling, large $d_k$ → large dot products → softmax gets peaked (near one-hot) → vanishing gradients. Dividing by $\sqrt{d_k}$ keeps variance stable. If $d_k=64$ then scale = 8.

Python — Self-Attention with W_Q, W_K, W_V 
import torch, torch.nn as nn, torch.nn.functional as F, math

class SelfAttention(nn.Module):
    def __init__(self, d_model, d_k, d_v):
        super().__init__()
        self.W_Q = nn.Linear(d_model, d_k, bias=False)
        self.W_K = nn.Linear(d_model, d_k, bias=False)
        self.W_V = nn.Linear(d_model, d_v, bias=False)
        self.scale = math.sqrt(d_k)

    def forward(self, X):
        Q = self.W_Q(X)  # [T, d_k]
        K = self.W_K(X)  # [T, d_k]
        V = self.W_V(X)  # [T, d_v]
        scores = (Q @ K.T) / self.scale  # scaled dot product
        alpha  = F.softmax(scores, dim=-1)
        Z      = alpha @ V
        return Z, alpha

# Arjun's example: 5 tokens, d_model=8 → d_k=d_v=4
attn = SelfAttention(d_model=8, d_k=4, d_v=4)
X = torch.randn(5, 8)
Z, alpha = attn.forward(X)
print("Z:", Z.shape, "alpha row sums:", alpha.sum(dim=-1))
$W_Q$, $W_K$, $W_V$ are the learned parameters. Updated via backpropagation during training — this is how the model learns to compute useful attention patterns.

Simple Self-Attention: 3 Steps
Step 1 — Scores ω

$\omega_{ij}=x^i\cdot x^j$ — dot product. Measures raw similarity. Output: [T×T].

Step 2 — Weights α

$\alpha=\text{softmax}(\omega)$ — probabilities. Each row sums to 1. Output: [T×T].

Step 3 — Context Z

$Z=\alpha X$ — weighted sum. Each $z^i$ encodes full sequence context. Output: [T×d].
